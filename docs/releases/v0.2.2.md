# WANGAI 0.2.2 — Startup recovery

- Fix the blank loading screen with `state not managed` after an update or launch.
  Both desktop webviews now start only after their command state is registered.
- Retry initial snapshot reads with bounded attempts and timeouts. If startup
  still fails, show an error and a Retry button instead of an endless spinner.
- Ignore cancelled and late snapshot results, including during Web Companion
  reconnection. Settings, audio, F8/F9 and Overlay behavior are unchanged.
- Strengthen isolated installer QA to require the actual Ready Room DOM before
  and after an update, including deliberately slow backend startup.

Settings and installation ID remain persistent. In-memory History still clears
when the application exits. This trial is not Windows Authenticode-signed;
Tauri updater signatures verify update integrity but do not remove the Windows
unknown-publisher warning.
